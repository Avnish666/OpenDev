## Exact owner sequence to finish the submission

1. [ ] Obtain the actual current hackathon/track rules and deadline; record official URLs,
   required versions/integration evidence, team/project requirements, allowed local-demo
   alternatives, artifact licenses, accessibility and video-duration rules. Confirm
   sponsor criteria individually; package installation/mock success is insufficient.
2. [ ] Verify repository visibility and judge access using an owner-approved account.
   A repository name is not proof reviewers can access the current pending work.
   Resolve historical credential revocation/incident review before wider sharing.
3. [ ] Review all pending Step 5/6 changes, notice inventory and screenshot privacy.
   Supply the authorized application license/contributor decision and any necessary
   vendor attribution. Confirm whether trial-evaluation material can be recorded/shared.
   Do not publish Studio bundles or screenshots without the required rights.
4. [ ] Reproduce the local demo on the recording machine using `../demo-setup.md`.
   Use a fresh synthetic DB, normal authorization and default-off features. Read the
   current test evidence and disclosure labels; do not use production credentials.
5. [ ] Record a 5–7-minute video using `demo-script.md`, actual screens and narration.
   Keep the local/synthetic label, actual deterministic mode and unverified-provider
   disclosures visible. Watch the full recording, remove secrets/private material,
   check audio/legibility and verify the organizer's file/duration rules.
6. [ ] Select the actual captured screenshots from `screenshots/`; use captions saying
   local synthetic evidence. Check the nine file hashes and ensure no personal data,
   cookies, raw private receipts or provider tokens appear. Optional Studio is not in
   these screenshots; do not claim it is.
7. [ ] After explicit owner approval only, execute the reviewed commit sequence in the
   final handoff, inspect staged files and rerun relevant checks. Push through the
   approved workflow, confirm remote SHA/judge access and tag only the reviewed demo
   candidate. No commit/push/tag was performed by Step 6.
8. [ ] Upload the actual approved video to an organizer-permitted location, check its
   access from a separate signed-out/private window and record the real resulting
   URL. No URL is invented in these documents.
9. [ ] Fill the organizer's actual form with `project-summary.md`, architecture and
   sponsor disclosures; supply only real repository/video links and truthful live
   status. If a public app URL is required, request the organizer's permitted local
   demonstration alternative while release blockers remain. Do not deploy merely
   to complete a form or claim an absent hosted endpoint.
10. [ ] Have the owner submit before the verified deadline, then retain the genuine
    confirmation/reference privately or redact it for the public record. Only after
    actual confirmation should the submission be marked completed.
